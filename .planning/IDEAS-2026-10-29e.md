## 1. Chụp màn thiết bị → agent, bấm vào view để ra code

**Vấn đề.** Khi sửa UI Android / Flutter, chủ nhân phải tự chụp màn hình, lưu, kéo vào agent, rồi tự tìm view đó nằm ở file nào.

**UI.**
- Thêm nút "Chụp" trên dòng thiết bị (tab Devices) và trên Run pane đang chạy. Ảnh hiện trong sheet xem trước, có hai lựa chọn: "Đính kèm vào agent" (vào khay attachments của pane agent cùng project, chủ nhân tự Enter) hoặc "Lưu".
- Chế độ "Soi view": vẽ khung các node lên ảnh. Bấm một node thì ra `resource-id` / `text` / `content-desc` / class, cùng các nút "Tìm trong code" (mở Find in Files với id hoặc chuỗi đó, khớp cả `strings.xml`) và "Điền vào agent" (`@layout/... id=..., bounds=...`).

**Nguồn / khả thi.**
- Desktop `devices/adb.ts:27` `createAdbCommands`: thêm `screencap` (`exec-out screencap -p`, timeout 10 s) và `uiDump` (`exec-out uiautomator dump /dev/tty`, parse XML trong `devices/parse.ts`, có test).
- IPC `ccm:dev-screencap|dev-uidump` đặt cạnh `devices/ipc.ts`. Ảnh đi vào attachments như cách `BrowserPane.vue:283` `screenshot()` đang làm.
- Tìm trong code dùng `ccm:search` có sẵn (`preview/search.ts`).
- Flutter không có id native nên chỉ dùng được `text` / `content-desc` (Semantics). Ghi rõ giới hạn này.

**Cỡ.** Vừa.

**Ràng buộc.** Chỉ chạy khi bấm, không giữ stream màn hình. Ảnh có thể chứa dữ liệu riêng tư, nên chỉ lưu trong data dir và chỉ khi chủ nhân bấm Lưu.

## 2. Bảng thử UI trên thiết bị: giao diện tối, cỡ chữ, ngôn ngữ, deep link

**Vấn đề.** App đa ngữ và có dark mode thì phải vào Settings của máy nhiều lần mỗi ngày. Mở deep link hay một activity cụ thể thì phải gõ `adb shell am start ...` bằng tay.

**UI.**
- Popover "Thử UI" trên thiết bị đang chọn, gồm:
  - Bật / tắt giao diện tối.
  - Cỡ chữ: 0.85 / 1 / 1.3 / 2.0.
  - Display size.
  - Ngôn ngữ riêng cho app (vi / en / …), lấy từ các thư mục `values-xx` của project.
  - Tắt animation.
  - Nút "Trả về như cũ", khôi phục giá trị đã lưu lúc mở popover.
- Mục "Mở…": danh sách activity exported và deep link (`<intent-filter>` có `<data scheme/host>`) đọc từ `AndroidManifest.xml` của project. Bấm thì chạy `am start`. Có ô nhập URI tự do.

**Nguồn / khả thi.**
- Các lệnh adb cố định, không qua shell: `cmd uimode night yes|no`, `settings put system font_scale`, `wm density`, `cmd locale set-app-locales <pkg> --locales` (Android 13+, máy cũ thì ẩn), `settings put global *_animation_scale`.
- Thêm `devices/uiToggles.ts` (pure, dựng argv, có test).
- Deep link: parser manifest pure. Package lấy từ run config sẵn có (`run/configs.ts`), launch dùng chung luồng ở `run/android/runner.ts`.
- Danh sách locale dùng lại parser `preview/i18nScan.ts` (v70).

**Cỡ.** Nhỏ–vừa.

**Ràng buộc.** Chỉ đổi khi bấm. Lệnh `settings put` đổi cấu hình máy, nên có nút khôi phục và báo rõ trên chip "đã đổi 2 cài đặt".

## 3. Bắt crash runtime từ Run pane → gói lỗi cho agent

**Vấn đề.** Lỗi build đã có nút gửi vào agent (`stores/run.ts:451` `sendErrorToAgent`). Crash lúc chạy (`FATAL EXCEPTION` trong logcat, `══╡ EXCEPTION CAUGHT BY ...` của Flutter, ANR) thì vẫn trôi trong log.

**UI.**
- Run pane hiện chip đỏ "Crash 12:03:41" khi gặp khối crash. Bấm vào thì mở khối đó đã gom (exception, message, stack frames).
- Frame thuộc project được tô đậm và bấm được để mở `file:line`.
- Nút "Điền vào agent" tạo đoạn ngắn: exception + 15 frame đầu của project + `@file:line`, prefill qua `insertInto`. Nhiều crash giống nhau thì gộp thành "×3".

**Nguồn / khả thi.**
- Log logcat có cấu trúc sẵn: `run/android/runner.ts:217` có `stream: 'logcat'`, kèm level / tag.
- Thêm `lib/runCrash.ts` (pure): `crashBlocks(lines)` gom theo tag `AndroidRuntime` + PID, khối Flutter theo dấu `══╡`, stack `at pkg.Class.method(File.kt:42)` / `package:app/x.dart 12:5`. Có test fixture.
- Nối với `lib/runUi.ts:39` `errorPrompt` và mở file qua `workspace.openFile`.

**Cỡ.** Nhỏ–vừa.

**Ràng buộc.** Parse trên buffer log đã có, không chạy thêm process nào. Dòng log có thể chứa token / email, nên đi qua mask (`log-mask.ts`) và cắt ≤ 4 KB trước khi điền.

## 4. Bộ chỉnh quyền: bớt hỏi permission lặp lại

**Vấn đề.** Khi nhiều agent chạy song song, phần lớn thời gian "chờ chủ nhân" là các prompt quyền lặp lại (`npm test`, `./gradlew`, `flutter analyze`). Mỗi lần như vậy agent đứng hàng phút.

**UI.**
- Panel "Quyền" theo project, mở từ Ctrl+K hoặc menu project. Panel có ba bảng:
  - Tool / lệnh đã hỏi quyền trong 7 ngày: số lần và tổng thời gian chờ.
  - Lệnh bị từ chối (đếm từ hook bridge).
  - Luật đang có trong `.claude/settings.json` / `settings.local.json`.
- Mỗi dòng có "Thêm luật allow" với gợi ý dạng `Bash(npm run test:*)`. Chủ nhân sửa được luật, xem diff file, rồi native confirm mới ghi.

**Nguồn / khả thi.**
- Episode chờ đã có: registry `waitingFor: permission prompt` (`collector/src/registry.ts:71`, docs §11n) cùng tên tool đang mở.
- Phần còn thiếu là tiền tố lệnh. Thêm sự kiện `PermissionRequest` vào hook bridge (`desktop/src/hooks.ts:7` `HOOK_EVENTS`, `scripts/hook-bridge.mjs`). Bridge chỉ ghi tool + **2 token đầu** của `command` (bỏ token có `=`, `/`, `\`, chuỗi dài, tức dạng secret / path), không ghi toàn bộ args.
  - Cần xác minh `PermissionRequest` có trên bản 2.1.289 và ghi vào docs. Nếu không có thì chỉ thống kê theo tên tool.
- Ghi luật: desktop `preview/permRules.ts` (đọc / merge `permissions.allow`, giữ nguyên key khác, có test), ghi theo cách giống `writeHooks` (`hooks.ts:60`), confirm qua `confirmRun`.

**Cỡ.** Vừa.

**Ràng buộc.** Không gửi gì cho agent và không tự thêm luật. Mỗi luật phải có confirm. Bỏ qua luật nguy hiểm (`Bash(*)`, `rm`): chỉ cảnh báo, không gợi ý.

## 5. "Ngữ cảnh nền": mỗi session khởi động đã tốn bao nhiêu context, do đâu

**Vấn đề.** CLAUDE.md, memory, skills, MCP server và plugin cứ phình dần. Mỗi agent mới mở ra đã ăn sẵn nhiều context, compact sớm hơn, nhưng chủ nhân không thấy con số nào.

**UI.**
- Thẻ "Ngữ cảnh nền" trong menu project, hoặc trong Usage. Thẻ gồm:
  - (a) **Số đo thật**: `contextTokens` của lượt trả lời đầu tiên trong các session gần đây của project (trung vị, xu hướng 14 ngày, mỗi session một chấm).
  - (b) **Nguồn tải** liệt kê theo kích thước KB / dòng: CLAUDE.md toàn cục → project → thư mục con, file `@import`, `MEMORY.md` và các file nó trỏ tới, skill, MCP server và plugin đang bật (từ Extensions).
- Bấm một file thì mở trong editor. Có cảnh báo "baseline tăng 18 % sau khi CLAUDE.md đổi ngày X".

**Nguồn / khả thi.**
- Collector `usage.ts` đã đọc `message.usage` từng record (`usageRecordOf`). Chỉ cần thêm `firstContext` cho mỗi transcript (input + cache write + cache read của record assistant đầu tiên, đúng công thức `Agent.contextTokens`), lưu trong cache usage. Thêm request `baseline.get { root }` theo kiểu `heatmap.get`, khai báo ở `packages/shared`.
- Danh sách file: desktop đọc kích thước (stat, không đọc nội dung ra renderer), lấy MCP / plugin từ `extensions/status.ts`.
- **Không quy đổi KB thành token** (luật "không bịa token"): chỉ token đo thật ở (a), còn (b) hiện KB.

**Cỡ.** Vừa.

**Ràng buộc.** Tính khi mở thẻ, dùng index sẵn có. Không lộ nội dung CLAUDE.md / memory, chỉ path + kích thước. Path trong `~/.claude` được phép (máy của chủ nhân).
