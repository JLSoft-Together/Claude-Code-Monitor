## 1. Kiểm accessibility màn hình trên thiết bị

**Vấn đề.** Play pre-launch report / Accessibility Scanner hay bắt lỗi thiếu `contentDescription`, nút quá nhỏ, chữ tương phản kém — chỉ biết sau khi upload.

**UI.** Dialog chụp màn (đã có view tree) thêm tab **Accessibility**: danh sách lỗi (icon + chữ `warning`), khung đỏ trên ảnh, bấm lỗi → tìm id trong project (đã có). **Điền vào agent**: "Sửa các lỗi a11y sau: id · loại · file".

**Khả thi.** Dùng lại `devices/uiDump.ts`: node clickable không text / content-desc; bounds < 48dp (chia density từ `wm density`); tương phản = lấy mẫu pixel chữ / nền trên ảnh chụp, công thức WCAG. Thuần parser, test được.

**Cỡ.** Nhỏ–vừa.

## 2. Hiệu năng app trên thiết bị (snapshot)

**Vấn đề.** Muốn biết màn có giật, app ăn bao nhiêu RAM, mở nguội bao lâu phải mở Android Studio Profiler.

**UI.** Devices → app → **Hiệu năng**: nút Đo → jank %, frame p50 / p90 / p99, RAM (PSS, Java / native heap), cold start ms. Giữ 10 lần đo gần nhất để so trước / sau khi agent sửa. **Điền vào agent** kèm số liệu.

**Khả thi.** `dumpsys gfxinfo <pkg>` (+ `reset` trước khi đo), `dumpsys meminfo <pkg>`, `am start -W -S` (cold start, confirm vì kill app). Parser thuần, lưu `<DATA_DIR>/perf/<pkg>.json`.

**Cỡ.** Vừa.

## 3. Quay màn hình thiết bị

**Vấn đề.** Bug kiểu animation / luồng nhiều bước một ảnh chụp không đủ.

**UI.** Dialog chụp màn thêm **Quay** (tối đa 30 s, nút Dừng). Xong: lưu MP4 (Save as) và **Đính kèm cho agent** dạng 4–8 khung hình rút từ lúc quay (Claude không đọc video).

**Khả thi.** `adb shell screenrecord --time-limit` + `pull`; khung hình = chụp `screencap` song song mỗi ~1 s trong lúc quay (không cần ffmpeg). Dọn file trên máy sau khi pull.

**Cỡ.** Nhỏ–vừa.

## 4. Trình duyệt file thiết bị

**Vấn đề.** Lấy file app export, log, ảnh chụp trên `/sdcard` hay đẩy file test vào máy vẫn phải gõ `adb pull/push`.

**UI.** Devices → **Files**: cây thư mục `/sdcard` (và `run-as` của app debug, nối v73), kéo thả từ Explorer / Windows để push, menu Pull về project / Mở / Xoá (confirm).

**Khả thi.** `adb shell ls -la` (parse, đọc khi mở thư mục), `pull` / `push` có tiến độ theo byte. Không watcher.

**Cỡ.** Vừa.

## 5. Kiểm trước khi phát hành app (Android / Flutter)

**Vấn đề.** Lỗi đắt khi lên store: quên tăng `versionCode`, release còn ad unit test AdMob, `debuggable` bật, minify tắt, targetSdk dưới mức Play yêu cầu, ký nhầm keystore.

**UI.** Run pane / Ctrl+K → **Kiểm phát hành**: checklist đỏ / xanh, mỗi dòng mở đúng file:line. Sau build: so chứng chỉ ký với SHA-256 đã nhớ cho project. **Điền vào agent** các mục đỏ.

**Khả thi.** Đọc tĩnh `build.gradle(.kts)`, `pubspec.yaml`, manifest (đã có parser v72 / v73), grep `ca-app-pub-3940256099942544` trong cấu hình release; `apksigner verify --print-certs` từ build-tools đã tìm được. Ngưỡng targetSdk là hằng có ngày cập nhật, không gọi mạng.

**Cỡ.** Vừa.

## 6. Lỗ hổng thư viện (OSV) trong bảng "Kiểm bản mới"

**Vấn đề.** v74 biết lib cũ nhưng không biết lib nào có CVE — đó mới là lý do phải nâng gấp.

**UI.** Bảng thư viện v74 thêm cột **Bảo mật** (số lỗ hổng, mức cao nhất, bản đã vá), lọc "chỉ lib có lỗ hổng". Prompt nâng cấp ưu tiên các lib này.

**Khả thi.** `POST https://api.osv.dev/v1/querybatch` (Maven / Pub / npm) chỉ khi bấm, chung cache 1 h với `LibChecker`. Chỉ gửi tên + version lib.

**Cỡ.** Nhỏ.

## 7. Tìm trong lịch sử session + Resume

**Vấn đề.** "Hôm trước session nào làm phần paywall?" — History chỉ có danh sách, không tìm theo nội dung đã yêu cầu.

**UI.** History → ô tìm: kết quả theo session (project, ngày, nhánh, đoạn prompt khớp đã che secret). Nút **Resume trong pane** (`claude --resume <id>`, như RestorePicker), **Mở thư mục**.

**Khả thi.** Quét `projects/**/*.jsonl` theo dòng khi bấm tìm, chỉ khớp record prompt của người dùng (không tool output), trả snippet ≤ 200 ký tự qua `log-mask`. Huỷ được, giới hạn 200 kết quả. Không lưu index nội dung.

**Cỡ.** Vừa.

## 8. Bác sĩ CLAUDE.md / memory

**Vấn đề.** v72 cho biết ngữ cảnh nền tốn bao nhiêu, nhưng không chỉ ra phần nào hỏng / thừa: memory trỏ tới file đã xoá, `[[link]]` không có đích, dòng `MEMORY.md` trỏ file không tồn tại, hai memory nói ngược nhau, CLAUDE.md quá dài.

**UI.** Từ dialog ngữ cảnh nền → **Kiểm tra**: danh sách vấn đề theo file, bấm mở đúng dòng. **Điền vào agent**: "Dọn memory theo danh sách sau".

**Khả thi.** Đọc CLAUDE.md (global + project + `@import`), thư mục memory của project; kiểm đường dẫn / tên file nhắc tới có tồn tại (chỉ token dạng path), link `[[ ]]`, frontmatter thiếu `name`/`description`, trùng `name`. Không sửa tự động.

**Cỡ.** Nhỏ.
