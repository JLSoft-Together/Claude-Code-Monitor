# Ý tưởng IDE / Workspace — 5 đề xuất (2026-10-28)

Bối cảnh: chủ nhân ưu tiên **IDE mượt** (không polling nặng, không jank, không process nặng chạy sẵn).
Office tạm dừng (v65) → không đề xuất gì cho Office. Ràng buộc cứng giữ nguyên: monitor không gửi
prompt / không gọi LLM (chỉ thao tác chủ nhân bấm mới gõ vào pane agent), local only, không database,
mọi chuỗi qua vue-i18n en/vi, Apple HIG.

## Đã có (khảo sát `.code_index/web.md`, `desktop.md`, `_meta.md`) — không đề xuất trùng

Split pane + tab group rail, Mission Control, zoom, undo close `--resume`, restore parked (v64), spawn
queue, Explorer + Atom icons, Quick Open (Ctrl/⌘+P), Terminal find, editor CodeMirror + auto save,
Changes pane (list/tree, inline + split diff, **discard file / hunk**), Git Log + branch toolbar
(create / ff / fetch / delete / push, nhiều tài khoản GitHub), **WorktreeMenu** (`wt.list|add|remove`,
mở agent trong worktree mới), Run pane Android/Flutter (+ `BuildError` → `sendErrorToAgent`), XML /
drawable / Flutter preview, browser pane + handoff (screenshot / console / element), attachments, MCP
`open_session`, Compact handoff, Devices adb, Extensions.

Khoảng trống phát hiện: IPC git **không có** `stage` / `commit` / `merge` (chỉ `ccm:changes-*`,
`ccm:git-branch-*`, `ccm:git-fetch|push`); không có tìm trong toàn project; worktree chỉ tạo / xoá,
không so với nhánh gốc hay gộp về; không có cách xem "agent đã đổi gì trong lượt vừa rồi"; lỗi
typecheck / test chỉ có cho Run Android/Flutter.

## Tham khảo thị trường (tóm tắt)

- **Conductor** (Mac): mỗi task 1 worktree; sidebar workspace, setup script (copy `.env`, cài deps
  vì worktree mới không mang file untracked / ignored), diff review, checks, merge / PR.
- **Cursor / Zed**: checkpoint theo lượt agent ("Restore Checkpoint"), Zed gom mọi sửa đổi của agent vào
  một multibuffer review → accept / reject từng hunk.
- **claude-squad / agent-manager / aque**: tmux + worktree, review rồi commit trước khi push; hàng đợi
  agent đang chờ.
- **Warp**: panel quản lý agent, thông báo Complete / Request / Error, badge tab (Orrery đã có tương
  đương: attention, toast, AttentionPopover).

Kết luận: phần Orrery còn thiếu so với các tool này nằm ở **vòng review → commit / merge**, không nằm
ở phần quan sát.

## 1. Review & Commit ngay trong Changes pane (ưu tiên cao nhất)

**Vấn đề.** Agent làm xong → chủ nhân xem diff trong Orrery nhưng muốn stage / commit thì phải sang
terminal (hoặc nhờ agent commit, tốn token và dễ commit nhầm file). Chạy 3–5 agent song song thì việc
gom thay đổi thành commit gọn là nút cổ chai.

**Cách làm.**
- Desktop `apps/desktop/src/preview/changes.ts`: thêm `stageFile` / `unstageFile` / `stageHunk`
  (dùng lại `hunkPatchFor` + `git apply --cached`, giống `discardHunk` nhưng không đụng working tree),
  `commit(root, message, { amend: false })` qua `execGit` (`-C`, không prompt, không `--no-verify`,
  hook của repo vẫn chạy). IPC `ccm:changes-stage|unstage|commit` trong `preview/ipc.ts` sau
  `isAppFrame` + `writeRoots`.
- `parseStatusV2` đã tách index / worktree → Changes pane hiện 2 nhóm Staged / Unstaged.
- Web `ChangesPane.vue` + `DiffView.vue` / `SplitDiff.vue`: nút Stage cạnh nút Discard ở mỗi hunk
  (`lib/diffBlocks.ts` `blockPatch` đã có), checkbox file, ô commit message ở đáy pane (Ctrl/⌘+Enter),
  "Đã xem" (reviewed) đánh dấu file theo hash nội dung, lưu sessionStorage, đổi nội dung → bỏ đánh dấu.
- Gợi ý message **không** dùng LLM: lấy tên nhánh / tên tab / tiêu đề session (`lib/title.ts`
  `displayTitle`) làm placeholder. Sau commit hiện nút Push sẵn có (`PushDialog.vue`).
- i18n module mới `workspace-commit.ts` (en/vi).

**Effort:** M.

**Độ mượt.** Không thêm watcher: `GitDirWatcher` đã watch `index` nên status tự cập nhật sau
stage / commit. Mọi lệnh git chạy khi bấm, ở main process, có timeout sẵn của `execGit`. Không đụng
TermPane.

**Rủi ro / câu hỏi.** Có cho `--amend` không (đề xuất: có, sau confirm native nếu commit đã push)?
Pre-commit hook chậm (lint-staged) → cần spinner + nút huỷ. Commit khi agent vẫn đang sửa file →
cảnh báo nhẹ nếu pane agent của root đó đang `busy` (`usePaneInfo` `isBusy`).

## 2. Checks pane — chạy typecheck / test / lint theo yêu cầu, lỗi bấm được

**Vấn đề.** Agent báo "xong" nhưng typecheck / test đỏ. Hiện chỉ Run Android/Flutter parse lỗi;
web/Electron (`npm run typecheck`, Vitest), `dart analyze`, `./gradlew lint` phải đọc log tay. Conductor
gọi đây là "checks" cho từng workspace.

**Cách làm.**
- Tái dùng `apps/desktop/src/preview/scripts.ts` `detectScripts` để gợi ý check (script tên
  `typecheck|test|lint|analyze`) + cấu hình tay theo project (lưu cạnh `layouts.json`, ví dụ
  `<dataDir>/checks.json`, validate giống `cleanLayout`).
- Chạy bằng `run/proc.ts` (đã có kill tree, `collect`); parser mới cạnh `run/parse.ts` cho định dạng
  phổ biến: `tsc` / `vue-tsc` (`file(line,col): error TS…`), Vitest, ESLint stylish, `dart analyze`,
  Kotlin/Gradle `e: file:///…:line:col`. Kết quả đưa về shared `BuildError` sẵn có.
- Web: pane kind mới `checks` (hoặc tab trong Run pane) — danh sách lỗi nhóm theo file, bấm mở
  `FilePane` đúng dòng; nút "Gửi lỗi cho agent" dùng lại `stores/run.ts` `sendErrorToAgent` →
  `workspace.insertInto` (chỉ prefill, không submit). Chip ✓/✗ trên header pane agent và card
  Mission Control.
- Tuỳ chọn opt-in "chạy check khi agent chuyển sang done" (mặc định tắt).

**Effort:** M.

**Độ mượt.** Không có gì chạy nếu chủ nhân không bấm (hoặc không bật opt-in). Tối đa 1 check / root,
toàn app tối đa 2 cùng lúc (giống `lib/spawnQueue.ts`), log ring giới hạn như Run pane, parse ở main
process theo dòng, gửi lỗi lên renderer theo lô (≤ 500 lỗi). Không JVM: Gradle chỉ chạy khi chủ nhân
bấm check Gradle.

**Rủi ro / câu hỏi.** Check nặng (Gradle) chạy song song agent đang build → tranh CPU; có nên khoá khi
Run pane cùng root đang chạy? Định dạng lỗi lạ → hiển thị log thô, không đoán.

## 3. Find in Files (Ctrl/⌘+Shift+F) bằng `git grep`

**Vấn đề.** Đã có Quick Open theo tên file nhưng không tìm được nội dung trong project; review code
agent viết ("còn chỗ nào gọi hàm cũ?") phải hỏi agent (tốn token) hoặc mở IDE khác.

**Cách làm.**
- Desktop: `preview/search.ts` chạy `git grep -n --column -I --no-color [-i] [-w] [-F|-E] -e <q>`
  (thêm `--untracked` để gồm file chưa track; ngoài repo thì fallback duyệt thư mục giới hạn) trong
  root được phép (`writeRoots` / `paneRoots`), giới hạn ≤ 2000 match, ≤ 200 ký tự/dòng, huỷ khi có
  query mới. IPC `ccm:search`. Không bundle ripgrep (tránh tăng size và binary theo OS).
- Web: panel thứ 3 trong `ExplorerPanel.vue` (Files | Changes | Search), danh sách windowed
  (`lib/rowWindow.ts`), highlight bằng `lib/fuzzy.ts` `highlightRuns`, bấm → `openFile` tới dòng;
  "Thêm vào prompt" dùng attachments sẵn có (`lib/promptAttachments.ts` `fileMention` dạng
  `@file:line`).
- Bước sau (không làm ngay): Replace trong file đã mở.

**Effort:** S–M.

**Độ mượt.** Chạy theo debounce 250 ms khi gõ, một tiến trình git / panel, kill tiến trình cũ;
không index nền, không watcher mới. `git grep` đọc thẳng index git nên rất nhanh trên repo cỡ này.

**Rủi ro / câu hỏi.** Repo có `node_modules` không ignore → `git grep` vẫn bỏ qua vì không track;
thư mục không phải git thì có cần hỗ trợ không? Regex do người dùng nhập → luôn truyền qua `-e`
argv, không qua shell.

## 4. Vòng đời worktree đầy đủ: setup → so với nhánh gốc → gộp về → dọn

**Vấn đề.** `WorktreeMenu.vue` đã tạo / xoá worktree và mở agent trong đó, nhưng: worktree mới thiếu
`.env`, `local.properties`, `google-services.json`, `node_modules` (lỗi Conductor cũng ghi nhận);
không có chỗ xem "nhánh này khác `master` thế nào"; gộp về phải gõ git tay; dọn xong vẫn còn nhánh.

**Cách làm.**
- Setup: danh sách file copy khi tạo worktree, cấu hình theo repo (mặc định gợi ý `.env*`,
  `local.properties`, `**/google-services.json`, `key.properties`), copy trong `pty/host.ts`
  `wt.add` sau `worktreeDest`; tuỳ chọn chạy 1 script setup (`npm install`, `flutter pub get`) trong
  pane shell mới — chủ nhân thấy và dừng được.
- So sánh: Changes pane chế độ "so với nhánh gốc" = `git diff <base>...HEAD` (merge-base) — dùng lại
  `preview/log.ts` `commitDiff` + `DiffView` / `SplitDiff`; header hiện ahead/behind so với base.
- Gộp về: nút "Gộp vào `<base>`" trong WorktreeMenu → native confirm (`main.ts` `confirmGit` sẵn có)
  → chỉ `merge --ff-only` hoặc `merge --squash` + commit (dùng commit của đề xuất 1); có conflict →
  dừng, mở Changes pane với mục `conflict` (kind đã có), không tự giải.
- Dọn: sau khi gộp, đề nghị xoá worktree + nhánh (`runDelete` sẵn có, không `--force`).
- Rail: nhãn worktree "đã gộp / chưa gộp / có conflict".

**Effort:** M.

**Độ mượt.** Toàn bộ là thao tác theo click. Trạng thái ahead/behind tính khi mở menu / khi
`GitDirWatcher` báo refs đổi, không poll. Copy file nhỏ, đồng bộ trong host PTY nhưng có giới hạn
kích thước (ví dụ ≤ 5 MB tổng, bỏ qua thư mục).

**Rủi ro / câu hỏi.** Copy file bí mật sang worktree: chỉ trong máy, nhưng cần chủ nhân xác nhận danh
sách mặc định. Gộp vào `master` khi checkout chính đang dirty → từ chối, báo rõ. Có muốn tạo PR GitHub
(dùng token v58) thay vì merge local không — để phase sau.

## 5. Checkpoint theo lượt agent — "agent đổi gì từ lượt trước", khôi phục file

**Vấn đề.** Một repo có nhiều lượt chat; Changes pane chỉ so với HEAD nên không biết lượt *vừa rồi*
sửa gì, và khi agent làm hỏng không có cách quay về trạng thái trước lượt mà không mất cả việc tốt
trước đó (Cursor / Zed đều có "Restore Checkpoint"; Claude Code có `/rewind` nhưng chỉ trong pane).

**Cách làm.**
- Mốc lượt: collector đã đọc transcript (user message mới = lượt mới, trạng thái `running` → `done`)
  → sự kiện nhẹ `turn` (terminalId, turnIndex, ts) trong protocol; không gửi nội dung prompt.
- Snapshot không đụng working tree / index của chủ nhân: desktop chạy `git add -A` với
  `GIT_INDEX_FILE` tạm + `git write-tree` + `git commit-tree` → lưu ref riêng
  `refs/orrery/cp/<session>/<n>` (hoặc kho git riêng trong `<dataDir>` nếu chủ nhân không muốn ghi vào
  repo). Giữ tối đa 20 checkpoint / session, xoá khi session bị quên (TTL).
- Web: trong Changes pane chọn "So với: HEAD | Trước lượt N | Trước session"; diff hai tree dùng lại
  `parseUnifiedDiff` + `DiffView`. "Khôi phục file / hunk về checkpoint" = `git checkout <cp> -- file`
  hoặc `git apply` ngược, sau confirm; ghi rõ không hoàn tác lệnh terminal / migration.

**Effort:** L.

**Độ mượt.** Snapshot chỉ chạy ở mốc lượt (vài lần / phút tối đa), bỏ qua nếu tree không đổi
(so `write-tree` hash), debounce theo root, chạy ở main process ngoài đường nóng TermPane;
`git add -A` trên repo lớn có thể tốn 100–500 ms → giới hạn 1 snapshot / root cùng lúc và bỏ qua
khi đang có snapshot chạy.

**Rủi ro / câu hỏi.** Ghi ref vào repo của chủ nhân có chấp nhận không (hiện app không ghi gì vào
`.git` ngoài lệnh chủ nhân bấm)? File ignored (`.env`, build) không được snapshot. Nhiều agent cùng
một checkout → checkpoint gồm thay đổi của agent khác; khuyên dùng worktree (đề xuất 4). Nên làm sau
1 và 4.

## Xếp hạng & thứ tự đề xuất

| # | Đề xuất | Effort | Lý do xếp |
|---|---|---|---|
| 1 | Review & Commit trong Changes pane | M | Đóng vòng "agent sửa → review → commit", dùng lại gần hết diff / hunk sẵn có |
| 2 | Checks pane | M | Bắt lỗi agent bỏ sót mà không tốn token, dùng lại Run parse + `sendErrorToAgent` |
| 3 | Find in Files (`git grep`) | S–M | Rẻ, dùng hằng ngày khi review, không index nền |
| 4 | Vòng đời worktree đầy đủ | M | Làm worktree thành cách chạy song song an toàn; cần commit (1) trước |
| 5 | Checkpoint theo lượt | L | Giá trị cao nhưng có câu hỏi về ghi ref vào repo; làm sau 1 + 4 |

Gợi ý sprint: (3) trước vì nhỏ → (1) → (2) → (4) → spike (5).
