# English

## Devices
- **Accessibility check**: in the device screenshot dialog, Accessibility lists views without a label, touch targets under 48 dp, low text contrast (estimated from the screenshot) and duplicate descriptions, frames them on the image, finds each in the project and fills a fix prompt with the files into the agent.
- **Screen recording**: Record in the screenshot dialog (up to 30 s, Stop any time), then Save as MP4 or attach evenly spaced frames to the agent; the file on the device is always removed.
- **App performance**: Performance on a device row measures one app when you click: janky frames, frame percentiles, memory and cold start time; keeps the last 10 measurements, shows better / worse against an earlier one and fills the numbers into the agent.
- **Device files**: Files browses shared storage and debuggable app folders; pull to a folder or the project, push by picking or dropping files, with progress and Cancel; new folder and delete (asks first).
- **Capture folder**: pick a folder in Settings › Screenshots and recordings; screen recordings are kept in recordings/, screenshots and frames reach agents as files in shots/ instead of the clipboard, and old files are cleaned after 7 days or past 2 GB.

## Tools
- **Library vulnerabilities**: in Check for updates, the Security button asks osv.dev (only library names and versions) and shows known vulnerabilities: count, worst severity, fixed version, advisory links, a "Vulnerable only" filter; Fill into agent lists vulnerable libraries first.
- **Release check**: Run pane or Ctrl+K checks an Android / Flutter app before publishing: versionCode raised since the last release, release build settings, targetSdk against Google Play's requirement, manifest risks, AdMob test ids, consent / billing / Firebase hints, and the signing certificate of the APK / AAB against the remembered release key. Each item opens at its line; Fill into agent lists the problems. Nothing is built.
- **Keep awake**: the computer does not sleep while a session, subagent or background job works and for 2 minutes after (only on power by default; the display can still turn off); a coffee cup in the header shows it.
- **Prompt samples and reopen after restart**: the prompt picker has 12 ready-made prompts you can duplicate or hide, and your library exports and imports as JSON. Settings › Startup can reopen the last workspace on its own; after a crash or a forced restart the restore card says so, ticks every project and brings shells back in the folder they were in.
- **Clean build output and low disk warning**: list and delete node_modules, build, .gradle, dist, target… of your projects (only git-ignored folders, after a confirm, never while something runs there); a top bar badge and one alert per drive when a drive Orrery or the agents write to gets below 10 GB or 5 %.

## Claude Code
- **CLAUDE.md / memory check**: in the background context dialog, Check lists broken memory links, index lines to missing files, unlisted memories, incomplete frontmatter, duplicate names, stale paths and oversized files; open each at its line or fill a cleanup prompt into the agent. Read-only.
- **Find a past session**: History (or Ctrl+K) searches what you asked Claude Code in earlier sessions, by project and range (7 / 30 / 90 days / all); each session shows its folder, start date, branch and up to 3 matching prompts with secrets masked. Resume in pane, Open folder or Copy session id. Scans only when you search; nothing is stored.
- **Forgotten processes**: Orrery measures RAM and CPU of each agent session and of the shells, dev servers, Gradle / Kotlin / Dart daemons and emulators around it, notices processes left behind by ended sessions, and sends one grouped alert when items sit idle past a threshold (60 minutes by default; Settings › Notifications › Forgotten after). Samples every 30 s only while Orrery is open or the alert is on.
- **Resources and ports**: the Resources button (header, Workspace rail) shows RAM / CPU of every session, shell, dev server, daemon and emulator, which ones are forgotten, and every listening port with its process (Open in a Browser pane, Copy). Stop one row or all forgotten items after one confirmation; a session in a Workspace pane is closed from its pane. When a tool call fails because a port is taken, Orrery names the process holding it.
- **Sensitive watch**: the session card (click it to list each hit) and an alert warn when an agent edits a secret file (.env, keystores, certificates, key.properties, google-services.json…) or a file outside its project, or runs git push --force, git reset --hard, git clean -fd, a recursive delete outside the project, adb uninstall or DROP TABLE. Open the file, open its diff when checkpoints are on, or ignore the rule for that project; Settings › Sensitive watch picks groups and adds your own patterns. Warns only, never blocks; commands and file contents are not stored.
- **Block next time**: on a sensitive warning, add a Claude Code deny rule (Edit(**/.env*), Bash(git push --force *)…) to this project's settings.json, its settings.local.json or your user settings after one confirmation showing the file and the change; other settings stay, the old file is kept as .orrery-bak, invalid JSON is never overwritten. Warnings with no exact rule (outside the project, DROP TABLE) have no button.
- **Phone notifications**: Settings › Phone sends to ntfy or a Discord webhook when a session waits for you, asks for a permission, finishes a job of 5 minutes or more, or the limit runs out, and the computer has been idle for a while (5 minutes by default). Off by default; only the app name, session alias or folder name, reason and waiting time leave the computer; at most 20 messages an hour; the URL and topic are kept in the system keychain.
- **Agent data**: Settings › Agent data shows what ~/.claude and ~/.codex hold by group, cleans old logs and caches, can remove images from old transcripts after backing them up, and moves either folder to another drive behind a link (Move back and Delete original included). Nothing changes without a confirmation.

# Tiếng Việt

## Thiết bị
- **Kiểm trợ năng**: trong dialog chụp màn thiết bị, Trợ năng liệt kê view thiếu nhãn, vùng chạm dưới 48 dp, chữ tương phản thấp (ước lượng từ ảnh chụp) và mô tả trùng, khoanh trên ảnh, tìm trong dự án và điền prompt sửa kèm file vào agent.
- **Quay màn hình**: nút Quay trong dialog chụp màn (tối đa 30 s, Dừng bất cứ lúc nào), rồi Lưu thành MP4 hoặc đính kèm các khung hình rải đều cho agent; file trên máy luôn được xoá.
- **Hiệu năng app**: nút Hiệu năng trên hàng thiết bị đo một app khi bấm: khung hình giật, phân vị thời gian khung, bộ nhớ và thời gian mở nguội; giữ 10 lần đo, hiện tốt hơn / kém hơn so với lần trước và điền số liệu vào agent.
- **File trên thiết bị**: nút File duyệt bộ nhớ dùng chung và thư mục app debug; kéo về thư mục hoặc dự án, đẩy bằng cách chọn hoặc thả file, có tiến độ và Huỷ; tạo thư mục và xoá (hỏi trước).
- **Thư mục chụp / quay**: chọn thư mục trong Cài đặt › Ảnh chụp và video quay; video quay giữ trong recordings/, ảnh chụp và khung hình tới agent dạng file trong shots/ thay vì clipboard, file cũ tự dọn sau 7 ngày hoặc khi quá 2 GB.

## Công cụ
- **Lỗ hổng thư viện**: trong Kiểm bản mới, nút Bảo mật hỏi osv.dev (chỉ tên và phiên bản thư viện) và hiện lỗ hổng đã biết: số lượng, mức cao nhất, bản đã vá, link cảnh báo, lọc "Chỉ lib có lỗ hổng"; Điền vào agent đưa lib có lỗ hổng lên đầu.
- **Kiểm phát hành**: Run pane hoặc Ctrl+K kiểm app Android / Flutter trước khi đăng: versionCode đã tăng so với lần phát hành trước, cấu hình bản release, targetSdk so với mức Google Play yêu cầu, rủi ro trong manifest, ID test AdMob, gợi ý consent / thanh toán / Firebase, và chứng chỉ ký của APK / AAB so với khoá phát hành đã nhớ. Mỗi mục mở đúng dòng; Điền vào agent liệt kê các lỗi. Không build gì.
- **Giữ máy thức**: máy tính không ngủ khi có session, subagent hay job nền đang chạy và thêm 2 phút sau (mặc định chỉ khi cắm sạc; màn hình vẫn tắt được); cốc cà phê trên header báo khi đang giữ.
- **Mẫu prompt và mở lại sau khởi động lại**: bảng prompt có 12 mẫu dựng sẵn để nhân bản hoặc ẩn, thư viện xuất / nhập được bằng JSON. Cài đặt › Khởi động có thể tự mở lại workspace lần trước; sau khi app tắt bất thường hay máy khởi động lại, thẻ khôi phục báo rõ, tích sẵn mọi project và đưa shell về đúng thư mục cũ.
- **Dọn đồ build và cảnh báo ổ đầy**: liệt kê và xoá node_modules, build, .gradle, dist, target… của các project (chỉ thư mục git ignore, sau khi xác nhận, không xoá khi đang có thứ chạy); badge trên thanh trên và một thông báo mỗi ổ khi ổ Orrery hay agent ghi vào còn dưới 10 GB hoặc 5 %.

## Claude Code
- **Kiểm CLAUDE.md / memory**: trong dialog ngữ cảnh nền, Kiểm tra liệt kê link memory gãy, dòng index trỏ file không có, memory chưa vào index, frontmatter thiếu, trùng tên, đường dẫn cũ và file quá lớn; mở đúng dòng hoặc điền prompt dọn dẹp vào agent. Chỉ đọc.
- **Tìm session cũ**: History (hoặc Ctrl+K) tìm theo những gì bạn đã hỏi Claude Code ở các session trước, lọc dự án và khoảng (7 / 30 / 90 ngày / tất cả); mỗi session hiện thư mục, ngày bắt đầu, nhánh và tối đa 3 prompt khớp đã che secret. Tiếp tục trong pane, Mở thư mục hoặc Chép id session. Chỉ quét khi bạn tìm, không lưu lại gì.
- **Process bỏ quên**: Orrery đo RAM và CPU của từng session agent cùng shell, dev server, daemon Gradle / Kotlin / Dart và emulator quanh nó, nhận ra process mồ côi do session đã kết thúc để lại, và gửi một thông báo gộp khi có mục nhàn rỗi quá ngưỡng (mặc định 60 phút; Cài đặt › Thông báo › Coi là bỏ quên sau). Chỉ lấy mẫu mỗi 30 s khi Orrery đang mở hoặc thông báo này bật.
- **Tài nguyên và cổng**: nút Tài nguyên (thanh trên, rail Workspace) hiện RAM / CPU của từng session, shell, dev server, daemon và emulator, cái nào bị bỏ quên, và mọi cổng đang lắng nghe kèm process (Mở trong pane Browser, Chép). Tắt từng dòng hoặc mọi mục bỏ quên sau một lần xác nhận; session trong pane Workspace được đóng từ pane. Khi một lệnh tool lỗi vì cổng đã bị chiếm, Orrery cho biết process nào đang giữ.
- **Canh nhạy cảm**: thẻ session (bấm để xem từng lần) và thông báo cảnh báo khi agent sửa file bí mật (.env, keystore, chứng chỉ, key.properties, google-services.json…) hay file ngoài project, hoặc chạy git push --force, git reset --hard, git clean -fd, xoá đệ quy ngoài project, adb uninstall hay DROP TABLE. Mở file, mở diff khi bật checkpoint, hoặc bỏ qua luật cho project đó; Cài đặt › Canh nhạy cảm chọn nhóm và thêm mẫu riêng. Chỉ cảnh báo, không chặn; không lưu lệnh hay nội dung file.
- **Chặn lần sau**: từ một cảnh báo nhạy cảm, thêm luật deny của Claude Code (Edit(**/.env*), Bash(git push --force *)…) vào settings.json hay settings.local.json của dự án hoặc cài đặt người dùng sau một lần xác nhận hiện file và thay đổi; cài đặt khác giữ nguyên, file cũ giữ thành .orrery-bak, không bao giờ ghi đè JSON lỗi. Cảnh báo không có luật khớp đúng (ngoài project, DROP TABLE) thì không có nút.
- **Báo ra điện thoại**: Cài đặt › Điện thoại gửi tới ntfy hoặc Discord webhook khi session chờ chủ nhân, xin quyền, xong việc từ 5 phút trở lên hoặc hạn mức sắp hết, và máy đã rảnh một lúc (mặc định 5 phút). Mặc định tắt; chỉ tên app, alias hoặc tên thư mục session, lý do và thời gian chờ rời khỏi máy; tối đa 20 tin mỗi giờ; URL và topic cất trong keychain của hệ thống.
- **Dữ liệu agent**: Cài đặt › Dữ liệu agent cho biết ~/.claude và ~/.codex chứa gì theo nhóm, dọn log và cache cũ, có thể gỡ ảnh khỏi transcript cũ sau khi sao lưu, và chuyển từng thư mục sang ổ khác sau một liên kết (có Chuyển về và Xoá bản gốc). Không gì thay đổi khi chưa xác nhận.
