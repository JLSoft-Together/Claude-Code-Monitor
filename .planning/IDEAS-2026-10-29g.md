## 1. Sao lưu / chuyển cấu hình sang máy khác

**Vấn đề.** Chủ nhân dùng nhiều máy (bug "session báo kết thúc" gặp ở máy khác). Mỗi máy phải dựng lại tab Workspace, alias, thiết bị nhớ, theme, font, ghi chú, hàng đợi prompt…

**UI.** Settings → **Sao lưu**: Xuất ra `orrery-backup-<ngày>.zip` / Nhập (xem trước danh sách mục, tick chọn, confirm). Tự giữ 1 bản trước mỗi lần cập nhật app (nối v74).

**Khả thi.** Gom `ccm.*` localStorage + file trong `CCM_DATA_DIR` (aliases, office-names, devices, notes). **Không** xuất token GitHub (keychain) — chỉ tên tài khoản, nhập xong nhắc thêm lại token. Đường dẫn project khác máy → map theo tên folder, mục không khớp để mờ.

**Cỡ.** Nhỏ–vừa.

## 2. Bảng chuỗi đa ngữ: `strings.xml` / ARB / i18n TS

**Vấn đề.** App Android / Flutter của chủ nhân nhiều ngôn ngữ; key thiếu dịch / thừa chỉ lộ khi chạy, mở từng `values-xx/strings.xml` rất mệt.

**UI.** Pane "Chuỗi": bảng key × locale, ô thiếu tô `warning`, lọc "chỉ key thiếu", sửa ô ghi thẳng file (giữ format / comment, confirm diff). Nút **Điền vào agent**: "Dịch các key thiếu sau sang vi, ja: …" (prefill). Cảnh báo placeholder lệch (`%1$s`, `{name}`) giữa các bản dịch.

**Khả thi.** Parse XML `<string>` / `<plurals>` / `<string-array>`, ARB JSON, file `en.ts` / `vi.ts` (dạng object literal đơn giản; phức tạp thì chỉ đọc). Quét khi mở pane, không watcher mới (dùng watcher Explorer sẵn có).

**Cỡ.** Vừa.

## 3. Kiểm phiên bản thư viện lỗi thời

**Vấn đề.** `libs.versions.toml`, `build.gradle(.kts)`, `pubspec.yaml`, `package.json` — muốn biết lib nào có bản mới phải tra tay từng cái.

**UI.** Explorer chuột phải file trên → **Kiểm bản mới**: bảng lib · đang dùng · mới nhất (stable) · loại (patch / minor / major, major tô `warning`). Bấm dòng → mở changelog / trang lib. **Điền vào agent** "nâng các lib sau, chạy build": prefill.

**Khả thi.** Gọi registry công khai chỉ khi bấm: Maven Central + Google Maven (`maven-metadata.xml`), pub.dev API, npm registry. Cache 1 h trong data dir. Không sửa file tự động.

**Cỡ.** Vừa.

## 4. Quản lý emulator Android (AVD)

**Vấn đề.** Tab Devices chỉ lo máy thật USB / Wi-Fi; mở emulator vẫn phải vào Android Studio.

**UI.** Devices → nhóm **Emulator**: danh sách AVD (tên, API, ABI), nút Chạy / Cold boot / Tắt / Wipe data (confirm). Emulator lên thì tự vào danh sách thiết bị như máy thật (mọi tính năng: cài APK, chụp màn, dữ liệu app…).

**Khả thi.** SDK đã tìm được cho adb → `emulator/emulator -list-avds`, `emulator -avd X [-no-snapshot-load]`, tắt = `adb -s emulator-5554 emu kill`. Đọc `~/.android/avd/*.ini` lấy API / ABI. Không polling: danh sách đọc khi mở tab.

**Cỡ.** Nhỏ.

## 5. Quản lý hook của Claude Code

**Vấn đề.** Chủ nhân cài nhiều plugin có hook (caveman, ECC session summary, statusline…); không biết hook nào đang chạy ở event nào, từ file nào, hook lỗi / chậm làm session khởi động lâu.

**UI.** Extensions → **Hooks**: bảng event (SessionStart, UserPromptSubmit, PreToolUse…) × nguồn (global `settings.json`, project, `settings.local.json`, plugin) × lệnh. Bật / tắt từng hook (ghi file, backup `.ccm-backup`, confirm diff — cùng cơ chế perm editor), **Chạy thử** với payload mẫu → thấy stdout / exit code / thời gian. Hook của Orrery (bridge) đánh dấu riêng, không cho tắt nhầm.

**Khả thi.** Đọc các file settings + `plugins/*/hooks/hooks.json` theo docs Claude Code 2.1.289 (kiểm định dạng trên bản cài trước, không đoán). Plugin hook chỉ đọc (tắt cả plugin qua Extensions sẵn có). Chạy thử = spawn lệnh với stdin JSON giả, timeout 10 s, chỉ khi bấm.

**Cỡ.** Vừa.
