## 1. Shell integration cho pane terminal (khối lệnh kiểu Warp / VS Code)

**Vấn đề.** Pane shell chỉ là luồng chữ: không biết lệnh nào xong, exit code bao nhiêu, chạy bao lâu; muốn đưa output một lệnh cho agent phải bôi đen tay.

**UI.**
- Mỗi lệnh có dấu ở lề: xanh (exit 0) / đỏ (≠ 0) + thời gian chạy; hover hiện lệnh + exit code.
- Ctrl/⌘+↑/↓ nhảy giữa các lệnh; menu dấu: Copy lệnh / Copy output / **Điền output vào agent** (prefill, nối với `sendErrorToAgent`) / Chạy lại.
- Lệnh chạy > 30 s xong khi pane đang ẩn → toast "build xong (exit 1, 2m14s)".

**Khả thi.** `pty/shellInit.ts` đã bơm OSC 7 (cwd) cho zsh; thêm OSC 133 (A/B/C/D + exit code) cho zsh, bash (`PROMPT_COMMAND`), PowerShell (`prompt` function wrap, như VS Code `shellIntegration.ps1`). xterm.js có `registerOscHandler` + `registerDecoration` / marker. Không parse ANSI, không đọc nội dung ngoài vùng người dùng bấm.

**Cỡ.** Vừa (PowerShell là phần khó). **Rủi ro:** profile người dùng tự đổi prompt (oh-my-posh, starship) — wrap sau khi profile chạy, hỏng thì tắt êm.

## 2. Thống kê công cụ / skill / subagent theo project

**Vấn đề.** Chủ nhân có ~200 skill + nhiều subagent type nhưng không biết cái nào thật sự được dùng, cái nào chỉ ăn context (nối với "Ngữ cảnh nền" v72).

**UI.** Thẻ trong Usage / History, lọc theo project + 7 / 30 ngày:
- Top tool (Bash, Edit, Read…), top skill (`Skill` tool_use `skill` name), top subagent type (`Agent` `subagent_type`), top MCP server (`mcp__<server>__*`).
- Cột "**chưa dùng trong 30 ngày**": skill / MCP server đang bật mà không lần gọi nào → gợi ý tắt (mở Extensions, không tự tắt).
- Tỉ lệ tool lỗi (`tool_result.is_error`) theo tool.

**Khả thi.** Collector `usage.ts` đã quét từng record (cache, `heatmap.get` làm mẫu). Chỉ đếm **tên** tool / skill / subagent type — không lấy input, đúng luật không lộ tool arguments. Danh sách skill đang có lấy từ thư mục skills (stat tên, không đọc nội dung). Cache usage tăng version → quét lại 1 lần.

**Cỡ.** Nhỏ–vừa.

## 3. Soi dữ liệu app trên thiết bị: SQLite / Room + SharedPreferences

**Vấn đề.** Debug app Android phải `adb shell run-as … ` rồi kéo file `.db` sang máy, mở tool khác; DataStore / SharedPreferences xem bằng tay.

**UI.** Tab Devices → chọn app (debuggable) → panel "Dữ liệu":
- `databases/*.db`: list bảng, xem hàng (phân trang, 200 hàng / trang), chạy SELECT tay (read-only).
- `shared_prefs/*.xml`: bảng key / type / value, sửa giá trị → ghi lại + `am force-stop` sau confirm, có nút **Khôi phục bản trước** (giữ bản gốc trong data dir — đúng luật "đổi máy phải có nút khôi phục").
- Nút "Điền schema bảng vào agent" (prefill).

**Khả thi.** `adb exec-out run-as <pkg> cat databases/x.db` (cả `-wal` / `-shm`, hoặc `sqlite3 .backup` nếu có) → file tạm → đọc bằng SQLite trong desktop (cần dep: `better-sqlite3` có prebuilt Electron, hoặc `sql.js` WASM để khỏi native module — nghiêng `sql.js`). App release không debuggable → báo rõ "chỉ build debug". Dùng `devices/adb.ts` sẵn có.

**Cỡ.** Vừa.

## 4. Phân tích kích thước APK / AAB + so với bản trước

**Vấn đề.** Bản release phình (ảnh, native lib, dex) mà chỉ biết khi lên Play Console.

**UI.** Explorer menu trên `*.apk` / `*.aab` (hoặc nút sau Build trong Run pane):
- Treemap / bảng: dex, `res/`, `assets/`, `lib/<abi>`, `resources.arsc`; top 20 file lớn nhất; số method dex nếu đọc header được.
- **So với bản trước** (chọn file thứ hai, hoặc bản build gần nhất app nhớ): +/− từng nhóm, file mới / mất.
- Manifest tóm tắt: versionCode/Name, minSdk/targetSdk, permission (đã có `devices/manifest.ts` parse manifest — kiểm có dùng lại cho AXML binary không).

**Khả thi.** Đọc zip central directory (compressed + uncompressed size) bằng Node, không cần SDK. AAB cùng là zip (`base/dex`, `base/res`…). Kích thước tải thật theo thiết bị cần `bundletool` — giai đoạn 2, chỉ nếu có sẵn.

**Cỡ.** Nhỏ–vừa.

## 5. Hết quota → hẹn tiếp tục lúc reset

**Vấn đề.** Agent dừng vì chạm giới hạn 5 giờ / tuần; chủ nhân phải canh giờ reset rồi vào từng pane gõ "tiếp tục".

**UI.**
- Pane / session dừng vì limit có nhãn "Chờ reset 14:30" + nút **Hẹn tiếp tục**.
- Đến giờ reset: toast + **điền sẵn** "tiếp tục" (hoặc prompt chủ nhân soạn) vào đúng các pane đã hẹn, focus pane đầu; chủ nhân tự Enter. Nối với hàng đợi prompt v70 (mục đầu hàng = lời hẹn).
- Không tự submit (luật zero-token, không dùng ngoại lệ Compact…).

**Khả thi.** `resetsAt` đã có (`PlanLimits.vue`, `UsageLimits.vue`, `useNotifications.ts:208`); toast limit đã có. Cần nhận diện "dừng vì limit" từ transcript / status (kiểm định dạng thông báo limit trên Claude Code 2.1.294 trước, không đoán). Một `setTimeout` tới giờ reset, không polling.

**Cỡ.** Nhỏ.
