## Ý 1 — Session / server bỏ quên (tốn RAM, CPU)

**Vấn đề:** session Claude / Codex mở lâu không dùng, cùng các process con (MCP server, background shell, dev server `npm run dev`…) vẫn ngốn RAM / CPU. Có cả process mồ côi: claude đã tắt nhưng server con vẫn sống.

**Hiện trạng:**
- `win-procs.ts` (koffi) chỉ đọc pid, ppid, name, creation time; command line chỉ `codex/processes.ts`. Chưa có RAM / CPU host nào.
- Collector không dựng cây process con của claude (docs §2). Desktop đã có `pty/owners.ts` `ownersOf`, `run/proc.ts` `nativeProcRows` để đi cây ppid.
- `TerminalSession.lastActivityAt` (`tracker.ts:586`), toast `stuck` dùng nó (`STUCK_CHOICES` trong `shared/notify.ts`).
- Kill đã có: pty `taskkill /T /F` (`pty/host.ts:238`), job `claude stop` (`job-stop.ts`). Chưa có kill session ở terminal ngoài.

**Đề xuất:**
1. Đo tài nguyên: Windows `GetProcessMemoryInfo` (private bytes, working set) + `GetProcessTimes` (kernel + user) qua koffi → CPU% theo delta; macOS `ps -o rss,%cpu`. Chu kỳ 30–60 s, không poll dày. Fallback PowerShell CIM khi `CCM_NATIVE_PROCS=0`.
2. Cây con mỗi session: con cháu của claude.exe / codex, phân loại: MCP stdio (khớp tên server trong cấu hình MCP), shell nền, dev server (có cổng LISTEN), khác. Tổng RAM / CPU của cả cây.
3. Session nhàn rỗi: process còn sống, trạng thái idle / waiting, `lastActivityAt` quá N phút (mặc định 60), không có subagent hay job chạy.
4. Server nhàn rỗi:
   - MCP: lần gọi tool cuối tới server đó (từ transcript, `usage.ts` `mcpServerOf`) quá N phút.
   - Dev server / shell nền: không có kết nối TCP established + CPU ≈ 0 trong N phút (không thể biết "được gọi" chính xác nếu không soi mạng → ghi rõ là ước lượng).
   - Mồ côi: tổ tiên claude đã chết → luôn gắn cờ.
5. UI: thẻ "Tài nguyên" (danh sách session / server bỏ quên, RAM / CPU, nhàn rỗi bao lâu), badge ở Mission Control; toast tuỳ chọn khi vượt ngưỡng (Settings → Thông báo).
6. Hành động, luôn qua confirm native, không tự kill mặc định: đóng pane Workspace (đường kill sẵn có); dừng server (kill cây); session ở terminal ngoài → kill cây claude (cảnh báo mất phiên đang mở, gợi ý `claude --resume`).

**Ràng buộc:** zero token; không đọc nội dung session ngoài thời điểm gọi tool; command line hiển thị đã che secret (`maskSecrets`).

## Ý 2 — Dọn / chuyển cache AI agent sang ổ khác

**Vấn đề:** dữ liệu Claude Code (`~/.claude`) và Codex (`~/.codex`) phình to trên ổ hệ thống.

**Đề xuất (cần Phase 1 kiểm thư mục thật trên Claude Code 2.1.294 / Codex 0.162 trước, không đoán):**
1. Quét dung lượng từng nhóm, đánh nhãn: *cache dọn được* (vd debug log, shell snapshot, cache plugin, cache npx / uv của MCP) vs *lịch sử* (transcript `projects/`, `sessions/` — mất là mất resume / History / thống kê của Orrery).
2. Dọn: chọn nhóm + "cũ hơn N ngày", xem trước số file / dung lượng, confirm native, chỉ khi không có session đang chạy dùng thư mục đó.
3. Chuyển ổ: copy sang ổ đích → kiểm → đổi tên bản gốc → junction (Windows `mklink /J`) / symlink (macOS) tại chỗ cũ; hoặc đặt `CLAUDE_CONFIG_DIR` / `CODEX_HOME`. Bắt buộc mọi claude / codex đã tắt; giữ bản gốc tới khi chủ nhân xác nhận rồi mới xoá; có nút hoàn tác.
5. Số đo máy này 2026-11-01 (`du`): `~/.claude` 11 G (`projects/` 9.4 G = transcript, `plugins/` 698 M, `file-history/` 80 M); `~/.codex` 6.0 G (`packages/` 881 M, `plugins/` 490 M, `cache/` 69 M, `logs_2.sqlite` 66 M; ~4.5 G còn lại nằm ở thư mục ẩn, `*` không bắt được → kiểm khi làm); `%APPDATA%/Claude` 11 G (app Claude desktop, ngoài phạm vi trừ khi chủ nhân muốn).
4. Collector / app phải theo đường mới (đã đọc `CLAUDE_CONFIG_DIR`, `CODEX_HOME`; junction thì trong suốt).
