# Ý tưởng IDE đợt 2 (2026-10-29)

Sau v67 (Find in Files, Review & Commit, Checks, Worktree lifecycle, Checkpoint). Ràng buộc giữ nguyên: IDE mượt (không index nền, không language server chạy sẵn, git chỉ chạy khi bấm / mở màn), không gửi prompt thay chủ nhân.

## 1. Review lượt agent: giữ / bỏ từng hunk

- Lượt agent đã có checkpoint `before:` / `after:` (`preview/checkpoints.ts`). Thêm màn "Lượt vừa rồi" diff `before → after` theo file, có nút **Giữ** / **Bỏ** cho từng hunk. Bỏ = `git apply -R` hunk đó vào worktree (patch dựng như `stageHunk`); nếu file đã đổi tiếp sau lượt thì `--check` fail → báo, không ghi.
- Chỗ gắn: `CheckpointsPanel.vue` (nút "Xem lượt"), tái dùng `DiffView` / `HunkPopup`; IPC mới `ccm:cp-revert-hunk`, confirm native khi bỏ cả file.
- Giá trị: giống Zed / Cursor "accept / reject", đúng vòng review của agent. Cần checkpoint đang bật.

## 2. Lỗi Checks hiện ngay trong editor (squiggle + F8)

- Kết quả `parseCheckOutput` (file, dòng, cột, message) đưa thành diagnostics `@codemirror/lint` cho file đang mở; gutter đỏ / vàng, F8 / Shift+F8 nhảy lỗi kế, tab file có chấm lỗi trong Explorer tree.
- Chỉ dùng kết quả lần chạy Checks gần nhất (không chạy lại khi gõ); đánh dấu "cũ" khi file đã sửa sau lần chạy.
- Chỗ gắn: `stores/checks.ts` → `CodeEditor.vue` / `FilePane.vue`, `ExplorerTree.vue`. Không đụng desktop.

## 3. Giải xung đột khi gộp / pull

- Hiện `mergeBranch` squash gặp conflict thì `reset --merge` và báo lỗi (`preview/worktrees.ts`). Thêm lựa chọn "Giữ lại để giải": để nguyên trạng thái merge, Changes hiện nhóm **Conflict**, mỗi khối `<<<<<<< / ======= / >>>>>>>` có nút **Lấy của mình / Lấy của nhánh / Lấy cả hai** + sửa tay, xong thì "Đánh dấu đã giải" (`git add`) và Commit / Huỷ gộp (`merge --abort`, confirm).
- Hay gặp khi nhiều agent chạy song song trên worktree rồi gộp về.
- Chỗ gắn: `preview/worktrees.ts`, `preview/changes*` (thêm trạng thái `U`), `ChangesPane.vue`, parser khối conflict mới trong `lib/` + test.

## 4. Tạo Pull Request + trạng thái CI của nhánh

- Từ WorktreeMenu / Git Log: "Tạo PR" cho nhánh đã push, dùng tài khoản GitHub sẵn có (v58, token trong keychain, chỉ main process gọi API). Tiêu đề / mô tả prefill từ các commit, chọn base, draft được; confirm native trước khi gửi.
- Badge trạng thái PR + checks (pass / fail / chạy) cạnh tên nhánh, chỉ lấy khi mở menu hoặc bấm làm mới (không polling).
- Chỗ gắn: `apps/desktop/src/github/` (`POST /repos/{o}/{r}/pulls`, `GET .../commits/{sha}/check-runs`), IPC `ccm:gh-pr-*`, `WorktreeMenu.vue`.
- Gửi dữ liệu ra ngoài (GitHub) → luôn sau confirm.

## 5. Blame theo dòng + nhảy sang Git Log

- Nút / phím "Blame" trong editor: chạy `git blame --porcelain` một lần cho file đang mở, gutter hiện tác giả · ngày ngắn, hover hiện tiêu đề commit, bấm mở commit đó trong Git Log pane (đã có). Tô nhạt dòng chưa commit.
- Tắt khi đóng; cache theo `HEAD` + mtime, huỷ khi file đổi.
- Chỗ gắn: desktop `preview/blame.ts` (abort như `search.ts`), IPC `ccm:git-blame`, `CodeEditor.vue` gutter, `log/` pane `focusCommit`.
